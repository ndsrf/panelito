## What Was Done

### Task 1 — workspace.tsx (WSL-02)

Extracted the inline `apiFetch` + `setMessages` body that previously lived only inside the `onMessagesRefresh` callback into a named `refreshMessages()` function declared in the `Workspace` component body (above the `useAIStream` call). The function is then:

- Passed directly as `onMessagesRefresh: refreshMessages` to `useAIStream` (replacing the inline arrow)
- Called via `setTimeout(refreshMessages, 300)` at the end of every `handleAfterSend` invocation

The 300ms delay lets the message POST commit to the database before the re-fetch runs. The `@analista` branch path is unchanged — it still calls `openAIStream` before the timeout fires.

### Task 2 — ai.ts (OBS-03)

Immediately after `await flushLangfuse()`, added two diagnostic log statements using `callbackHandler.last_trace_id` (typed `string | null` in `@langfuse/langchain`):

- If set: `console.log('[ai] Langfuse trace flushed:', callbackHandler.last_trace_id)` — confirms callbacks fired and the trace UUID
- If null: `console.warn('[ai] Langfuse trace ID is null after flush — callbacks may not have fired')` — signals the LangChain callbacks never set a trace ID

This distinguishes two failure modes: (a) trace created but not exported to dashboard, vs. (b) CallbackHandler callbacks never fired at all.
