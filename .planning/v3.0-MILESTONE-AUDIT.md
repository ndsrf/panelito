# Milestone v3.0 Audit — "The Bots Must Help the Conversation Flow"

**Audited:** 2026-07-19T08:13:55Z

**Score:** 22/28 requirements satisfied

## Summary

Phases 10–14 all show "Complete" in ROADMAP.md, but **only Phase 13 has a VERIFICATION.md** — Phases 10, 11, 12, and 14 were never formally verified after execution. This audit filled that gap by cross-referencing REQUIREMENTS.md traceability, SUMMARY.md frontmatter, and (via a spawned integration checker) direct reads of the current source code, since phase-level verification artifacts weren't available to trust.

The good news: the **reactive flow** (human message → LangGraph → Role node → ArgGraphBuilderNode → ProfileBuilderNode → Skills → speech filter → Langfuse) is fully and correctly wired, including two requirements (PROFILE-01, TRIGGER-02) that a stale Phase 13 VERIFICATION.md had marked failed but which subsequent gap-closure plans (13-06, 13-07) demonstrably fixed.

The bad news: the **proactive flow** — the TriggerEngine's own `setInterval` silence-trigger, which is the flagship mechanism Phase 14 was built to deliver — bypasses the token budget guard, the arbitration lock, the argGraph, and participant-profile personalization almost entirely. Those four systems (Phases 10, 11, 13) were built and tested against the reactive path but never actually threaded into the one proactive path that exists. Additionally, there is no working deployment path for the standalone server that runs the TriggerEngine at all — as shipped, it's unclear the milestone's core proactive-bot promise runs in production.

## Cross-Phase Integration Findings

See `gaps.integration` and `gaps.flows` in the frontmatter above for the structured list. In short:

1. **BOT-01/BOT-02 only guard the proactive silence-trigger path.** The token budget circuit breaker and arbitration lock, built in Phase 10 as universal safety infrastructure ("No bot fires without these in place" — Phase 10 goal), are never invoked from any of the 5 reactive Skill-triggered paths (moderation, drift-redirect, fact-check, orphan-edge, phase-readiness), which fire on every human message and are the dominant source of bot LLM spend. `12-CONTEXT.md` D-06 explicitly promised these paths would keep routing through `bot-arbitrator.ts`/`bot-budget.ts` — they don't.

2. **The proactive silence-trigger runs "blind."** Because BOT-04's dual `:human`/`:bot` thread_id split is thread-isolated (not branch-isolated) for checkpoint state, the TriggerEngine's silence-triggered Coach invocation never sees the `argGraph` built on the human thread, and never receives a `participantId` for profile personalization. Both GRAPH-01 (as literally worded) and PROFILE-02 are broken specifically on this path — the one proactive trigger phases 10–14 delivered.

3. **TRIGGER-07 has no real deployment path.** `server.ts` (which runs the TriggerEngine) is never invoked by the actual Vercel deployment; the root README describes a fully serverless architecture that contradicts running it. No deployment doc for the standalone server exists despite REQUIREMENTS.md's claim that a manual step is documented.

4. **Old interim silence-scan loop cleanly removed** — no duplicate-trigger-firing risk found; `silence-scan.ts` no longer exists on disk.
