<objective>
Perform the D-07/D-08 Skill/Role decoupling refactor: separate each Skill's `detect()`/`buildPromptGuidance()` implementation from its Role binding so one heuristic body can back multiple per-Role `Skill` instances without code duplication.

This is a locked-decision refactor (D-07/D-08). It is deliberately narrow: it changes only the export SHAPE of `moderation.ts` and `fact-check.ts` (free functions + a `makeXSkill(role)` factory + preserved named exports) and the construction call sites in `skills.ts`. It does NOT change the `Skill` interface, the `COACH_SKILLS`/`ANALYST_SKILLS` membership or priority order, or any detection behavior. It does NOT implement the deferred "Dynamic Agent Composition" vision (D-09) — no display names, no multiple named instances per Role, no agent-builder UI.

Per D-06, this refactor deliberately adds NO Blueprint-level heuristic toggle: the "skip unless something fires" behavior is not a new Blueprint-configurable option. Heuristics remain Role-scoped and code-defined (owned by the Role, minted by the `makeXSkill(role)` factories), not surfaced as Blueprint-level dynamic configuration.

Purpose: Make future multi-Role heuristic reuse a one-line factory call instead of a copy-paste, per the locked D-07/D-08 decision. No file overlap with any other Phase 15 plan.
Output: `moderation.ts` and `fact-check.ts` refactored to the factory shape; `skills.ts` wired to the factories; all existing tests green.
</objective>
