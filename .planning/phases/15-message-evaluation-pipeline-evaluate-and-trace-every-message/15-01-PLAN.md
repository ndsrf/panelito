<objective>
Add the graph-topology contracts that make a cheap "evaluate every message" entry point possible, plus the two small contract edits its consumer (Plan 15-03) depends on.

This plan introduces a new `triggerType` value `passive_eval` that routes `START → triggerGate` directly, bypassing orchestrator/agent/argGraphBuilder for the overwhelmingly-common "evaluated, nothing fired" case (zero LLM cost — D-05). When a Skill DOES fire, the new branches route it through argGraphBuilder (so the Role node has argGraph context — Pitfall 2) into its Role node. It also adds a backward-compatible role-keyed personality fallback to both Role nodes (so a `passive_eval` fired reply gets the correct Coach vs Analyst voice) and extends `runArbitration`'s signature with the optional `firingSkillRole` param the reactive path needs for Analyst arbitration (Pitfall 4 / D-11).

Purpose: Provide the graph + arbitration contracts before the message-evaluation service (Plan 15-03) is written against them — interface-first ordering, no scavenger hunt for the executor.
Output: `graph.ts` routing extensions + pathsMaps, Role-node personality fallbacks, `runArbitration` signature extension, and graph routing unit tests.
</objective>
