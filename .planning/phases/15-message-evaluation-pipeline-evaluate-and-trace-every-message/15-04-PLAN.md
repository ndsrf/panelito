  <what-built>
    A new server-side, fire-and-forget evaluation path (`evaluateMessageAsync`) that runs on every human message insert: it invokes the graph via the new `passive_eval` entry (START -> triggerGate, zero-LLM for the common case), always emits a Langfuse trace tagged `trigger:passive-eval` (D-04), escalates to a paid tier only when a tier-1 heuristic matches, and — when a Skill fires — delivers a Coach/Analyst reply gated by the newly-wired budget + arbitration guards (D-11/D-12). The existing @analista-tag and power-reaction paths are untouched.
  </what-built>
  <how-to-verify>
    Precondition: the standalone Node API server is running with a valid creator BYOK key and Langfuse credentials configured (same setup Phase 14 used for its TriggerEngine live check). Use a session whose Blueprint enables the Coach and/or Analyst bot.

    1. Send a plain, untagged, unreacted, benign message (e.g. "buenos dias a todos") in a live session. In the Langfuse dashboard, confirm a NEW trace appears tagged `trigger:passive-eval` for that message, and that it shows essentially zero LLM generation cost (tier-1 did not match -> no paid call). This is the core D-04 + EVAL-02 evidence and directly exercises the A1 fire-and-forget-completes-in-the-deployed-runtime risk.
    2. Send several more untagged benign messages; confirm each produces a `trigger:passive-eval` trace and that token/cost counts on those traces stay flat (no escalation).
    3. Send a message that matches a tier-1 heuristic (e.g. a clearly rude/insulting message for moderation, or a checkable factual claim like "El agua hierve a 50 grados" for fact-check). Confirm the trace shows escalation to a paid tier and, budget/arbitration permitting, a Coach or Analyst reply appears in chat attributed to the correct bot name (Facilitador / Verificador), NOT to the human creator.
    4. Regression: send an `@analista ...` message and separately apply a power reaction (fire/pin/target). Confirm both still stream a full agent response exactly as before Phase 15 (EVAL-03 no-regression).
    5. Optional cost check: if you send a burst of many messages, confirm the budget circuit breaker suppresses further bot replies while still leaving evaluation traces visible (D-12 silent-but-traced suppression).

    Note the known pre-existing WSL2 Supabase Realtime limitation (documented since Phase 9 / reaffirmed in 14-07): a proactively/reactively inserted bot reply may only appear after a manual refresh in local WSL2 dev — this is out of scope and must NOT be treated as a Phase 15 regression; verify the reply ROW exists (DB/refresh) rather than requiring live push.
  </how-to-verify>
