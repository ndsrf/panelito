<objective>
Build the new fire-and-forget per-message evaluation path — the heart of Phase 15 — and wire it into the message-insert route.

Per D-03, this evaluation path is a new, separate, lightweight path — realized as an in-process fire-and-forget function call (`evaluateMessageAsync`), NOT an HTTP endpoint and NOT an extension of the existing `/invoke` SSE endpoint. The in-process function-call shape chosen here IS the D-03 decision realized: the send critical path stays untouched and the evaluation runs as an isolated, unawaited server-side call after the 201 is prepared.

`evaluateMessageAsync` is invoked (unawaited, fail-silent) after every human message insert. It resolves the session/blueprint/provider, invokes the graph with the new `triggerType: 'passive_eval'` entry (Plan 15-01), and — for the common "nothing fired" case — terminates cheaply at TriggerGateNode while still emitting a Langfuse trace tagged `trigger:passive-eval` (D-04). When a Skill fires, it applies the D-11/D-12 budget + arbitration gate (now reaching the reactive path for the first time, closing the BOT-01/BOT-02 audit gap) and, if allowed, inserts a correctly-attributed bot reply. It mirrors `trigger-engine.ts`'s `scanBranch` almost verbatim, adapted from per-tick to per-message.

Purpose: Make moderation/fact-check/all Skills reachable on ordinary untagged messages (the `260719-e9x` gap) at near-zero cost, with per-message observability and cost/arbitration safety.
Output: `message-evaluation.ts` (service + sentinel + constants), its test suite, and the 3-line fire-and-forget wiring in `messages.ts`.
</objective>
