<objective>
Close CR-01 (Critical, code review) / PROFILE-01 Truth 1 verification gap: `profileBuilderNode` currently groups `state.argGraph.nodes` by the freeform LLM-extracted `speaker` string, resolves `author_id` independently per speaker-group, then issues one FULL-REPLACE upsert per group. When two speaker labels (e.g. "Miguel" and "miguel") resolve to the SAME `author_id` within a single node invocation, the second upsert silently discards the first group's positions/assertions (the `upsert_participant_profile` RPC does `positions = EXCLUDED.positions`, not a merge).

Fix locus decision (BLOCKING schema-push requirement resolved): **application-side merge-before-upsert, NO SQL change.** Resolve `author_id` first, union all argGraph nodes across every speaker label that resolves to the same `author_id`, compute positions/assertions from that union, then call the EXISTING full-replace `upsert_participant_profile` RPC exactly once per resolved author. Because each author is upserted exactly once per invocation with its complete union, the existing full-replace contract is respected — no migration 0017, no `supabase db push`, no schema-push task is needed. (Cross-invocation full-replace remains correct: `profileBuilderNode` re-derives the complete per-author set from the accumulated `state.argGraph` each turn.)

Purpose: The "stated positions / key assertions" data must be reliable for the realistic case of one participant cited under label drift (nicknames, capitalization) across a 100-message extraction window.
Output: Refactored `profileBuilderNode` + a regression test that would have caught this originally.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LLM-extracted `speaker` label → profile identity | `ArgNode.speaker` is an untrusted freeform string; it must NEVER be the profile key. Identity is the `author_id` resolved server-side from the `messages` table via `message_id`. |
| ArgGraph node content → participant_profiles.positions/assertions | User-authored claim labels flow into a durable per-participant store. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-13-06-01 | Tampering/Spoofing | profileBuilderNode identity attribution | mitigate | Group/merge by RESOLVED `author_id` (messages-table lookup, role='user' filter), never by the freeform `speaker` label — a manipulated/ drifting display name cannot cause data to be attributed to, or overwritten for, the wrong participant. |
| T-13-06-02 | Information Disclosure | cross-participant position leakage during merge | mitigate | Phase-1 union only concatenates nodes whose citing message resolves to the SAME `author_id`; distinct authors remain in distinct `byAuthor` buckets, so one participant's positions can never merge into another's row. |
| T-13-06-03 | Repudiation/Integrity | silent data loss (the CR-01 defect itself) | mitigate | One upsert per resolved author with the complete union eliminates the second-writer-wins overwrite; existing full-replace RPC + RLS (service-role-only writes, row-ownership SELECT) unchanged. |
