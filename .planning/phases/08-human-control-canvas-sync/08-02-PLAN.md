<objective>
Create the database foundation for the Mic Check Pattern: two new nullable columns on the branches table and two PostgreSQL RPC functions for atomic lock acquisition and release.

Purpose: The mic lock must be enforced at DB level (not application level) because two near-simultaneous /invoke calls on serverless can race. The Postgres `UPDATE ... WHERE ... RETURNING` pattern in try_acquire_mic provides atomic compare-and-set — if the WHERE clause matches nothing, no UPDATE happens and `FOUND` is false. This is the same pattern as `increment_ai_count` in migration 0003.
Output: Migration file 0010_mic_lock.sql applied to local Supabase dev. No application code changes in this plan — that's Plan 04.
</objective>

    SECTION 1 — ALTER TABLE to add mic lock columns to the branches table:
    ```
    ALTER TABLE public.branches
      ADD COLUMN IF NOT EXISTS mic_holder_id   text        NULL,
      ADD COLUMN IF NOT EXISTS mic_acquired_at timestamptz NULL;
    ```
    Add COMMENT ON COLUMN for both columns explaining their purpose (HUMAN-01 reference).

    SECTION 2 — try_acquire_mic function:
    - Signature: `try_acquire_mic(p_branch_id uuid, p_holder_id text, p_expiry_seconds int DEFAULT 30)`
    - Returns: `TABLE(acquired boolean, held_since timestamptz)`
    - Language: `plpgsql` (needs IF FOUND)
    - SECURITY DEFINER, SET search_path = public
    - Logic: UPDATE branches SET mic_holder_id = p_holder_id, mic_acquired_at = now() WHERE id = p_branch_id AND (mic_holder_id IS NULL OR mic_acquired_at < (now() - (p_expiry_seconds || ' seconds')::interval))
    - IF FOUND: RETURN QUERY SELECT true, now()
    - ELSE: RETURN QUERY SELECT false, mic_acquired_at FROM branches WHERE id = p_branch_id
    - Use `(p_expiry_seconds || ' seconds')::interval` — NOT `make_interval()` (safer across Postgres versions per RESEARCH.md A2)

    SECTION 3 — release_mic function:
    - Signature: `release_mic(p_branch_id uuid)`
    - Returns: void
    - Language: `sql`
    - SECURITY DEFINER, SET search_path = public
    - Logic: UPDATE public.branches SET mic_holder_id = NULL, mic_acquired_at = NULL WHERE id = p_branch_id

    SECTION 4 — GRANT statements:
    - GRANT EXECUTE ON FUNCTION public.try_acquire_mic(uuid, text, int) TO service_role;
    - GRANT EXECUTE ON FUNCTION public.release_mic(uuid) TO service_role;

    Follow the exact SQL style of migration 0003 (lowercase CREATE OR REPLACE, uppercase SQL keywords inside functions, consistent indentation). Do NOT include DOWN migration — Supabase uses forward-only migrations.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-02-A | Denial of Service | try_acquire_mic — concurrent /invoke flooding same branch | mitigate | Atomic Postgres UPDATE WHERE returns acquired=false for concurrent callers; route returns 409 mic_locked; 30-second expiry prevents permanent lock from crashed function (D-06/D-07) |
| T-08-02-B | Tampering | mic_holder_id column — caller supplies p_holder_id string | accept | p_holder_id is the sessionId set by the route (not user-controlled input from request body); it's used as a lock identity string, not for access control decisions |
| T-08-02-C | Availability | Mic lock not released on Vercel function crash | mitigate | 30-second expiry check on next try_acquire_mic call; expired lock is stolen atomically by the new caller (D-07); finally block also releases on normal completion (D-06) |
| T-08-02-SC | Tampering | npm/pip/cargo installs | accept | No new packages installed in Plan 02; this is a SQL migration only |
</threat_model>
