# Phase 8 — UI Design Contract: Human Control + Canvas Sync

> Visual and interaction contract for Phase 8 frontend surfaces. Generated by gsd-ui-researcher.
>
> **Scope note:** Phase 8 is predominantly a backend phase. The frontend surface is narrow:
> - One new affordance: "Advance Phase" button (HUMAN-02, creator-only)
> - Two new SSE event types handled in `useAIStream`: `phase_signal`, `mic_locked`
> - Four new Realtime broadcast events handled in `useSessionChannel`: `mic_acquired`, `mic_released`, `canvas_update`, `phase_advanced`
> - Session-store and Zustand state extensions for `currentPhase`, `micLocked`
> - No new pages, no new routes, no new layout changes
>
> Phase 9 owns the Graph Canvas frontend (@xyflow/react). Do not implement any canvas rendering here.

## Surface Specifications

### Surface 1: "Advance Phase" Affordance (HUMAN-02)

**Who sees it:** Session creator only. Non-creators never see this affordance.

**Location:**
- Desktop: inside the existing analytics panel creator controls bar (same row as Analistas / Ramas / Freeze buttons)
- Mobile: inside the `Sheet` bottom drawer under a new `border-t` section titled "Fase actual"

**States:**

| State | Visual |
|-------|--------|
| `phase_signal` not yet received (or `null`) | Button `variant="outline"` size="sm" `h-9 gap-2` with `ChevronRight` icon. Label: "Siguiente fase". Disabled. Opacity 60%. |
| `phase_signal === true` received | Button `variant="default"` (indigo primary fill) size="sm" `h-9 gap-2` with `ChevronRight` icon. Label: "Avanzar fase". Enabled. Subtle pulse animation via `animate-pulse` for one cycle only. |
| PATCH pending | Button disabled, label: "Avanzando...". Spinner icon replaces `ChevronRight`. |
| PATCH success | `toast.success('Fase avanzada.')`. Button returns to outline/disabled state (signal consumed). |
| PATCH 403 (not creator) | Never shown — button is gated by `session.creator_id === user.id` in component. |
| PATCH 400 (invalid phase) | `toast.error('No hay una fase siguiente en este Blueprint.')`. Button returns to outline/disabled state. |

**Phase name display:** Alongside the button, render a `Badge variant="secondary"` showing the `current_phase` name (read from `session-store.currentPhase`). Label format: just the phase name string from the blueprint, e.g. "Formulación de Hipótesis". Font: 13px, weight 400. Badge renders even when button is disabled.

**Interaction contract:**
- On button click: `POST`-style — call `PATCH /sessions/:id/phase` with `{ next_phase_id }`. The `next_phase_id` comes from the `phase_signal` SSE payload field `current_phase_id` — the frontend knows which phase is ready from the SSE event.
- Clicking fires immediately — no confirmation dialog. Phase advance is non-destructive.
- After success, consume the signal: reset button to disabled outline state; update `currentPhase` in store.
- The `phase_signal` flag in the store is reset to `false` after any PATCH attempt (success or error).

**Accessibility:**
- `aria-label`: `"Avanzar a la siguiente fase"` when enabled; `"Esperando señal del analista"` when disabled.
- Disabled state uses `disabled` attribute — no `aria-disabled`.

### Surface 2: Mic Lock Indicator (HUMAN-01)

**Who sees it:** All participants — but the visual treatment differs.

**Purpose:** The mic lock is a bot concurrency guard (not human turn-taking). The UI hint is subtle — it reinforces that AI is working, not that a human is blocking.

**Visual:**
- When `mic_acquired` broadcast received for the active branch: set `micLocked = true` in session-store. The existing AI streaming bounce dots in `InputBox` already communicate "AI is working". No new UI element needed for `micLocked` in Phase 8 — the streaming dots are sufficient.
- When `mic_released` broadcast received: set `micLocked = false` in session-store.
- If the `/invoke` call returns HTTP 409 `{ error: 'mic_locked' }`: set `status = 'mic_locked'` in `AIStreamStatus` type. Display: `toast.error('El analista ya está respondiendo en esta rama.')` — no other UI change. The input box remains usable for human message sending (the mic lock only blocks `/invoke`, not `/messages`).

**`AIStreamStatus` addition:** Add `'mic_locked'` to the union:
```
'mic_locked'  // 409 from /invoke — another graph run in progress on this branch
```

**Existing error display in `InputBox`:** No changes needed to `InputBox` for mic_locked. The toast is sufficient. The existing `isAIStreaming` state already shows bounce dots while streaming is in progress.

---

### Surface 3: Canvas Update Reception (CANVAS-02)

**Who sees it:** All participants. Phase 8 only receives and stores — Phase 9 renders.

**Frontend contract:**
- When `canvas_update` broadcast received in `useSessionChannel`, store `{ nodes, edges }` in the session-store (or a dedicated canvas store if preferred, but session-store extension is consistent with existing patterns).
- Do NOT attempt to render nodes or edges in Phase 8. The `@xyflow/react` canvas is Phase 9.
- Log receipt: `console.log('[canvas] update received', nodes.length, 'nodes', edges.length, 'edges')`.
- Store shape: `canvasNodes: CanvasNode[]` and `canvasEdges: CanvasEdge[]` in session-store. Initialize as empty arrays.

---

### Surface 4: Phase Advanced Reception (HUMAN-02)

**Who sees it:** All participants when creator advances phase.

**Frontend contract:**
- When `phase_advanced` broadcast received in `useSessionChannel`: update `currentPhase` in session-store to `new_phase_id`.
- Show `toast.success('La sesion ha avanzado a la siguiente fase.')` for all participants (including creator).
- Non-creator participants: no button affordance — toast only.

## Interaction Contracts

### SSE Event Handling in `useAIStream`

Add handling for two new SSE event types in the existing `while (true)` read loop:

| SSE Event | Handler |
|-----------|---------|
| `phase_signal` | Parse `{ current_phase_id: string, blueprint_id: string }`. Store `phaseSignal = true` + `pendingPhaseId = current_phase_id` in component state (or lift to session-store). Enable the "Advance Phase" button for the creator. |
| `mic_locked` (409 response, not SSE event) | Already handled via HTTP status — set `status = 'mic_locked'`, show toast (see Surface 2). |

Note: `phase_signal` arrives as an SSE event BEFORE the `done` event (per RESEARCH.md Pitfall 6 ordering). The consumer must handle it inside the `for (const block of parts)` loop.

### Realtime Event Handling in `useSessionChannel`

Add four new `.on('broadcast', ...)` handlers to the existing channel subscription:

| Broadcast Event | Handler |
|-----------------|---------|
| `mic_acquired` | `useSessionStore.getState().setMicLocked(true)` — only if `payload.branch_id === activeBranchId`. |
| `mic_released` | `useSessionStore.getState().setMicLocked(false)` — only if `payload.branch_id === activeBranchId`. |
| `canvas_update` | `useSessionStore.getState().setCanvasData(payload.nodes, payload.edges)` |
| `phase_advanced` | `useSessionStore.getState().setCurrentPhase(payload.new_phase_id)` + `toast.success(...)` |

Branch-ID filtering for mic events: compare `payload.branch_id` to `useSessionStore.getState().activeBranchId`. Only apply if branch matches — prevents cross-branch lock state bleeding.

## Animation Contract

| Element | Animation | Duration | Easing |
|---------|-----------|----------|--------|
| "Advance Phase" button on signal received | `animate-pulse` (Tailwind built-in) | 1 cycle (~2s), then stop | ease-in-out |
| Toast notifications | sonner default slide-in | 300ms | ease-out |
| All other elements | None | — | — |

The pulse is a one-shot signal: start on `phase_signal === true` receipt, stop when button is clicked or signal is consumed. Implementation: `useState(false)` for `pulsing`, set to `true` on signal, `false` on click.

Do not use Framer Motion for Phase 8. The single-pulse affordance is achievable with Tailwind's `animate-pulse` class toggled via conditional classname.
