    SECTION 3 — bot_circuit_state table (one row per branch): `branch_id uuid PRIMARY KEY REFERENCES public.branches(id) ON DELETE CASCADE`, `circuit_open boolean NOT NULL DEFAULT false`, `reset_at timestamptz`, `updated_at timestamptz NOT NULL DEFAULT now()`.

    SECTION 4 — sessions budget threshold column (D-06): `ALTER TABLE public.sessions ADD COLUMN IF NOT EXISTS bot_budget_threshold int NOT NULL DEFAULT 1000;` (1000 tokens per 5-minute window = 200 tokens/min). Comment it as the per-session-overridable budget ceiling.

    SECTION 5 — try_acquire_bot_lock(p_branch_id uuid, p_bot_id text, p_locked_until timestamptz) returns table(acquired boolean): plpgsql, security definer, set search_path = public. Atomic INSERT ... ON CONFLICT (branch_id) DO UPDATE SET locked_until = excluded.locked_until, winner_bot_id = excluded.winner_bot_id WHERE bot_arbitration.locked_until IS NULL OR bot_arbitration.locked_until < now(). Use FOUND to decide acquired true/false (same compare-and-set contract as try_acquire_mic — grant only when unlocked or expired).

    SECTION 6 — release_bot_lock(p_branch_id uuid) returns void: sql, security definer, set search_path = public. UPDATE bot_arbitration SET locked_until = NULL, winner_bot_id = NULL WHERE branch_id = p_branch_id (mirrors release_mic).

    SECTION 7 — check_and_record_bot_budget(p_branch_id uuid, p_tokens_used int) returns table(allowed boolean, circuit_open boolean, tokens_used_window bigint): plpgsql, security definer, set search_path = public. Logic in one call (D-07):
      a) Read/ensure a bot_circuit_state row for the branch. If circuit_open is true AND reset_at > now(): return (false, true, 0). If circuit_open true AND reset_at <= now(): reset circuit_open=false (10-min pause elapsed).
      b) Read the threshold from sessions.bot_budget_threshold for the session owning this branch (join branches → sessions).
      c) INSERT the invocation into bot_budget_ledger (branch_id, invoked_at=now(), tokens_used=p_tokens_used).
      d) SUM tokens_used from bot_budget_ledger WHERE branch_id=p_branch_id AND invoked_at > now() - interval '5 minutes' into v_window.
      e) If v_window > threshold: upsert bot_circuit_state SET circuit_open=true, reset_at = now() + interval '10 minutes'; return (false, true, v_window). Else return (true, false, v_window).

    SECTION 8 — RLS + grants: `ALTER TABLE ... ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| service_role → Postgres RPC | Server-side bot invoker calls RPCs with branch/token inputs |
| authenticated user → bot tables | Participants must NOT read/write budget or lock state |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-03 | Elevation of Privilege | bot_arbitration / bot_budget_ledger / bot_circuit_state | mitigate | RLS enabled with no permissive policy for authenticated role; access only via security-definer RPCs granted to service_role (participants cannot read/tamper lock or budget state) |
| T-10-04 | Tampering | concurrent try_acquire_bot_lock calls | mitigate | Atomic INSERT...ON CONFLICT...WHERE expired compare-and-set; only one caller wins per window by construction (same proof as try_acquire_mic) |
| T-10-05 | Denial of Service | bot budget explosion on creator BYOK key | mitigate | check_and_record_bot_budget trips circuit at threshold and returns allowed=false for a 10-minute reset window |
| T-10-06 | Repudiation | budget usage accounting | mitigate | bot_budget_ledger is append-only with invoked_at; windowed SUM is auditable |
</threat_model>
