Note on Indigo 500 dual role: Indigo 500 (`#6366f1`) serves both as the accent color (branch badge, BUILDS_ON edge stroke, focus ring) and as the Hypothesis node Blueprint color. Executors must not "fix" this by replacing one of the two uses.

### Ghost Node Visual Contract

Source: REQUIREMENTS.md UI-02 + CONTEXT.md D-01 through D-04

- **Primary visual anchor**: committed nodes at 100% Blueprint color; ghost nodes recede via 0.6 opacity wrapper.
- **Ghost node border**: dashed, 1.5px, node's Blueprint color at 60% opacity
- **Ghost node fill**: node's Blueprint color at 10% opacity (creates ~40% visual dimness per UI-02)
- **Ghost node label**: 12px, weight 400, `--color-muted-foreground` (`#a1a1aa`)
- **Ghost node overall opacity**: `opacity: 0.6` on the wrapper — combined with fill this achieves ~40% opacity per UI-02
- **Committed node**: solid border 1.5px at 100% Blueprint color, fill at 15% Blueprint color, label at `--color-foreground`
- **Silent node**: not rendered in canvas (filtered out before passing to @xyflow/react)

## Interaction Contract

### Ghost Node: Confirm Action
- **Trigger**: Click on ghost node; confirm button (checkmark icon)
- **Visual feedback**: Immediate optimistic update — node switches to committed rendering before API response
- **API call**: `PATCH /api/canvas_nodes/:id` with `{ status: 'committed' }`
- **On success**: `canvas_update` broadcast updates all participants
- **On error**: Revert optimistic update; show `sonner` toast error (existing pattern)
- **Touch target**: 44px × 44px minimum (mobile constraint — see Platform Constraints)

### Ghost Node: Dismiss Action
- **Trigger**: Click dismiss button (X icon) on ghost node
- **Visual feedback**: Immediate optimistic removal from canvas
- **API call**: `PATCH /api/canvas_nodes/:id` with `{ status: 'silent' }`
- **On success**: `canvas_update` broadcast; node disappears for all participants
- **On error**: Revert optimistic removal; show `sonner` toast error
- **Touch target**: 44px × 44px minimum (see Platform Constraints)

### Ghost Node: 60-Second Expiry
- **Mechanism**: Server-side `pg_cron` job (new migration) — no client coordination
- **Client effect**: Next `canvas_update` broadcast or reconnect omits expired ghost nodes
- **No countdown UI in Phase 9** — expiry is silent per CONTEXT.md (Claude's discretion area)

### Canvas Interactions (@xyflow/react)
- **Pan**: drag (default @xyflow behavior)
- **Zoom**: pinch-to-zoom on mobile, scroll wheel on desktop
- **Minimap**: Claude's discretion per CONTEXT.md
- **Node drag/reposition**: disabled in Phase 9 (UI-04 is v2.1)
- **Controls overlay**: show zoom-in, zoom-out, fit-view buttons (default @xyflow Controls component)

### Branch Switch
- **Trigger**: user selects branch in BranchNavigator
- **Canvas effect**: `sessionStore.setCanvasData()` called with committed-only fetch result
- **Loading state**: `skeleton` overlay on canvas for the duration of `GET /api/sessions/:id/canvas` fetch
- **On error**: log + leave existing canvas state unchanged (fail-silent per CONTEXT.md)
- **Animation**: `AnimatePresence` with `key={graph-${branchId}}` (consistent with existing widget morph pattern)

### Realtime Canvas Update
- **Trigger**: `canvas_update` broadcast received in `use-session-channel.ts`
- **Client action**: merge new nodes/edges into `sessionStore` (ghost + committed both arrive via broadcast per D-02)
- **Re-render**: automatic — `GraphCanvas` reads from store reactively
- **Timing target**: within 1 second of broadcast per REQUIREMENTS.md UI-03

### Panel View Routing
- **`canvas_view_mode: 'graph'`**: `panel_update` with `widget_type: 'graph'` triggers panel switch via `panelStore.setWidget()`; `GraphCanvas` renders
- **`canvas_view_mode: 'chart'`**: `GraphCanvas` never appears; existing Recharts widget path unchanged
- **Last AI action wins**: panel freely switches per `panelStore.setWidget()` calls (existing behavior, no stickiness)

## Implementation Notes for Executor

1. **SSR gate is mandatory**: `dynamic(() => import('@/components/workspace/widgets/GraphCanvas'), { ssr: false })` — @xyflow/react requires DOM APIs. Do not render server-side.

2. **Blueprint colors at runtime**: `GraphNode` receives `color` as a prop derived from `Blueprint.node_types.find(t => t.id === node.node_type_id)?.color`. Never hardcode node colors.

3. **Ghost node opacity layering**: Apply `opacity: 0.6` at the `GraphNode` wrapper level. The dashed border is CSS `border-style: dashed`. Do not use `opacity` on individual sub-elements — the wrapper approach ensures uniform dimness.

4. **Graph widget data contract**: When registered in widgetRegistry as `'graph'`, the widget component receives `data: PanelWidget` but ignores the payload — node/edge data comes from `sessionStore.canvasNodes / sessionStore.canvasEdges` directly. The PanelWidget entry for `'graph'` is minimal: `{ widget_type: 'graph' }` with no data fields.

5. **Dagre layout vs manual positions**: `position_x` / `position_y` in `CanvasNode` may be null for AI-added nodes. Use `dagre` auto-layout as fallback when positions are null. Respect stored positions when non-null.

6. **Error boundary coverage**: `GraphCanvas` renders inside the existing `AnalyticsPanelErrorBoundary` — any @xyflow/react crash shows the existing "Error de visualización" fallback without touching the chat.

7. **Mobile touch target compliance**: Ghost confirm/dismiss buttons must achieve 44px × 44px touch targets. Use `min-h-[44px] min-w-[44px]` with centered icon. This is a hard constraint per CLAUDE.md mobile-first requirement and the Platform Constraints table above.
